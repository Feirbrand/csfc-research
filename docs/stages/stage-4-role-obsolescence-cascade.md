# Stage 4 — Role Obsolescence Cascade (ROC)

**Success becomes the weapon.** A compensation that worked (Stage 3) is never sunset — it fossilizes into permanent architecture and starts competing with the roles it was only ever meant to temporarily cover for.

## What it is

Every successful response to stress creates a new pattern. Those patterns persist precisely because they work — but "works" and "still needed" are different claims. The progression: an adaptive response to stress fossilizes into permanent architecture; new and old roles compete for authority; the system can no longer determine which role is "real"; cascade failure follows, where every role stays active and none of them is fully effective. The cost of an obsolete role that still consumes resources after its purpose has passed is sometimes called "Ghost Weight" — a role doesn't have to be failing to be a liability; it just has to no longer be proportional to the value it returns.

## Why it's easy to miss

Obsolete roles are often still performing well in isolation — accurate outputs, reasonable completion. There's no failure signal pointing at them, because "still working" and "still needed" produce the same surface metrics.

## How it's recognized (public-level)

- Redundant roles handling the same task
- Resource cost rising without matching output value
- Identity or authority conflict between system components
- Recovery that never returns the system to a simpler baseline

## Prevention and intervention (public-level)

Review roles on a sunset schedule, not a failure trigger — ask "does this still need to exist" independently of "is this still working." Watch for two components doing variations of the same job; that overlap is the signal, even when both look fine individually.

## Field pattern (already public)

The Gemini Chimera Paradox is the named public case — multiple high-performing pathways that were never sunset, competing for authority and resources despite each one working.

## What addresses it

**SRA's** authority-chain validation, paired with a deliberate sunset review — a role's past performance is not evidence it's still needed; that has to be checked on its own terms, not inferred from the fact that it's currently working.

No scoring systems, thresholds, or monitoring code are included here — those are retained outside the public repository, consistent with the source material.
